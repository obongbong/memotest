# 메모장 프로그램

Python으로 만드는 로컬 메모장 프로그램입니다. UI와 서버를 모두 Python으로 작성하고, 데이터베이스 대신 JSON 파일을 저장소로 사용합니다.

## 1. 프로젝트 목표

- 메모를 생성하고 목록으로 확인할 수 있다.
- 메모를 열어 수정하고 삭제할 수 있다.
- UI와 데이터 처리를 FastAPI 서버를 통해 분리한다.
- 별도의 DB 설치 없이 파일만으로 데이터를 보존한다.
- 기능을 작게 시작하고, 이후 검색과 태그 기능을 확장할 수 있는 구조를 만든다.

## 2. 기술 스택

| 영역 | 기술 | 사용 목적 |
| --- | --- | --- |
| 언어 | Python 3.11+ | 전체 애플리케이션 개발 |
| UI | Tkinter | 데스크톱 메모장 화면 |
| 서버 | FastAPI | 메모 CRUD API 제공 |
| 서버 실행 | Uvicorn | FastAPI 애플리케이션 실행 |
| HTTP 통신 | Requests | UI와 서버의 통신 |
| 데이터 검증 | Pydantic | API 요청과 응답 모델 검증 |
| 저장소 | JSON 파일 | DB를 대신하는 영속 저장소 |
| 테스트 | Pytest, FastAPI TestClient | 저장소와 API 검증 |

## 4. 전체 구조

```text
memotest/
├─ README.md
├─ requirements.txt
├─ data/
│  └─ notes/                  # 메모 JSON 파일 저장 위치
├─ client/
│  ├─ main.py                 # UI 실행 진입점
│  ├─ api.py                  # FastAPI 호출 클라이언트
│  └─ views/
│     ├─ main_window.py       # 메모 목록과 전체 창
│     └─ editor.py            # 메모 편집 화면
└─ server/
   ├─ main.py                 # FastAPI 앱 생성과 라우터 등록
   ├─ models/
   │  └─ note.py              # 요청/응답 데이터 모델
   ├─ routes/
   │  └─ notes.py             # 메모 API 엔드포인트
   ├─ services/
   │  └─ note_service.py      # 메모 업무 규칙
   └─ storage/
      └─ file_storage.py      # JSON 파일 읽기/쓰기
```

### 계층별 책임

```text
Tkinter UI
    ↓ requests
FastAPI routes
    ↓
Note service
    ↓
File storage
    ↓
data/notes/{note_id}.json
```

- `client`: 사용자의 입력을 받고 API를 호출한다.
- `routes`: HTTP 요청과 응답, 상태 코드를 담당한다.
- `services`: 제목 기본값, 시간 기록 등 업무 규칙을 담당한다.
- `storage`: 파일 경로와 JSON 입출력만 담당한다.
- `models`: API에서 주고받는 데이터의 형태를 정의한다.

## 5. 메모 데이터 형식

메모 하나를 JSON 파일 하나로 저장합니다. 파일명은 `id.json` 형식을 사용합니다.

```json
{
  "id": "a-note-id",
  "title": "오늘 할 일",
  "content": "프로젝트 구조 정리하기",
  "created_at": "2026-09-18T09:00:00+00:00",
  "updated_at": "2026-09-18T09:30:00+00:00"
}
```

규칙:

- `id`는 메모를 식별하는 고유 값이다.
- `title`이 비어 있으면 `제목 없음`을 사용한다.
- 날짜와 시간은 ISO 8601 형식의 UTC로 저장한다.
- 목록 조회 시 `updated_at`이 최신인 메모부터 보여준다.
- 저장 디렉터리는 실행 위치가 아니라 프로젝트 루트 기준으로 계산한다.

## 6. API 설계

기본 주소: `http://localhost:8000`

| Method | 경로 | 설명 |
| --- | --- | --- |
| `GET` | `/health` | 서버 상태 확인 |
| `GET` | `/notes` | 메모 목록 조회 |
| `GET` | `/notes/{note_id}` | 메모 한 건 조회 |
| `POST` | `/notes` | 메모 생성 |
| `PUT` | `/notes/{note_id}` | 메모 수정 |
| `DELETE` | `/notes/{note_id}` | 메모 삭제 |

생성/수정 요청 예시:

```json
{
  "title": "메모 제목",
  "content": "메모 내용"
}
```

존재하지 않는 메모를 조회·수정·삭제하면 `404 Not Found`를 반환합니다.

## 7. 실행 방법

프로젝트 루트에서 의존성을 설치합니다.

```bash
pip install -r requirements.txt
```

서버를 실행합니다.

```bash
uvicorn server.main:app --reload
```

다른 터미널에서 UI를 실행합니다.

```bash
python -m client.main
```

서버와 UI는 각각 별도의 프로세스로 실행합니다.

## 8. 개발 순서

1. `Note` 모델과 JSON 저장소의 생성·조회·수정·삭제를 구현한다.
2. 서비스 계층에서 ID 생성, 시간 기록, 기본 제목 규칙을 구현한다.
3. FastAPI 라우트를 연결하고 `404` 등 오류 응답을 정한다.
4. API 테스트로 CRUD와 파일 저장 결과를 검증한다.
5. Tkinter에서 메모 목록과 편집 화면을 구현한다.
6. UI에서 생성·수정·삭제 API를 연결한다.
7. 서버가 꺼져 있거나 파일이 손상된 경우의 오류 화면을 보완한다.
8. MVP가 안정화된 뒤 검색과 태그를 추가한다.

## 9. 초기 설계에서 정한 범위

- 이 프로젝트는 단일 사용자 로컬 앱을 우선한다.
- 인증과 다중 사용자 동기화는 MVP에서 다루지 않는다.
- 파일 충돌을 줄이기 위해 한 메모는 하나의 JSON 파일로 관리한다.
- 데이터가 커지거나 여러 기기에서 공유해야 할 때 SQLite 또는 별도 DB 도입을 검토한다.
- UI가 저장소 파일을 직접 읽지 않고 항상 API를 통해 서버와 통신하도록 한다.
